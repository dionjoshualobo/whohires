### Slide 2: Breaking the Myth — 4 High-Impact Non-Code Pathways (2.5 Mins)

*Demystify the misconception that open source requires writing C++ or systems code on day one. 80% of project friction lives outside the codebase.*

* **1. Documentation & Technical Writing (Highest Need):**
* *The Problem:* Maintainers write code, but rarely write beginner-friendly setup guides.
* *Actions:* Clarifying vague `README.md` steps, updating broken installation instructions, writing step-by-step tutorials, or translating docs into regional languages.


* **2. UI/UX & Product Design:**
* *The Problem:* Developer-built tools often have unintuitive interfaces and clunky user flows.
* *Actions:* Auditing user journeys, submitting Figma redesigns for dashboard views, improving CLI terminal outputs, and fixing web accessibility (a11y) issues.


* **3. Issue Triage & Quality Assurance:**
* *The Problem:* Maintainers are swamped with hundreds of duplicate or vague bug reports.
* *Actions:* Reproducing bugs reported by other users, asking for missing system logs, labeling tickets, and verifying fixes on different operating systems.


* **4. Community Management & DevRel:**
* *Actions:* Organizing local community meetups, answering newcomer questions on GitHub Discussions or Discord, and writing monthly release notes.

## A few things that will make the segment more effective

1\. Don't spend too long explaining GSoC. Most CS students have probably heard of it. Explain how to find an organization, interact with mentors and prepare a proposal instead.

2\. Give non-code contributions equal importance. Otherwise, the audience will assume this is just another session telling them to make GitHub PRs.

3\. Use Frappe as a recurring example. Introduce its business model in the first section, its contribution ecosystem in the second, and its career opportunities in the third. This also gives the other speaker's Frappe reference a meaningful place.

4\. Don't promise that open-source contributions automatically get you hired. Explain that they give you demonstrable experience, a public portfolio and relationships with people working on real software.

5\. End with something actionable. Give everyone a task they can do the same day: find one project they use, read its contribution guidelines and make one useful contribution this month.
